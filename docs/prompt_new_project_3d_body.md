## 给承接方的主 Prompt（从这里开始复制）

### 背景与目标

- 主产品是一个 **微信小程序**（健身私教），技术栈为 **微信原生 + Node 后端**。主仓库里已有 **`threejs-miniprogram` + GLTFLoader + 本地 GLB 加载** 的演示（小黄鸭），路径在 `miniprogram/components/body-gltf/`、`miniprogram/libs/gltf-loader.js` 等。
- 你需要在一个 **独立的新项目**（本 Prompt 所指的项目）中完成：**可商用授权的人体 glTF/GLB 资产管线** + **可在浏览器或简单 Node 脚本中验证的「按身高、围度驱动骨骼缩放」原型**，最终产出 **交付物清单** 与 **接入说明**，供主仓库拷贝资源与对接代码。
- 身体数据字段（业务侧，单位一般为 cm）：身高、体重、体脂、胸围、腰围、臀围、大臂围、大腿围、小腿围（可无）、性别。映射逻辑请参考同目录文档 **`bone_mapping_draft.md`**（比例用「测量值 / 参考值」，不依赖固定真人模特）。

### 硬性约束

1. **输出格式**：主交付为 **单文件 GLB（glTF 2.0 二进制）**；若用 glTF 文件夹，须说明如何打成 GLB。
2. **运行环境**：目标运行环境为 **微信小程序** 内的 **threejs-miniprogram**（Three.js r108 量级），**不要**依赖 Node.js 在端上跑模型；验证阶段可用 **浏览器 Three.js** 或 **glTF Viewer**。
3. **包体**：单文件 GLB 建议控制在 **≤ 3MB**（越小微越好）；若超，须给出 **Draco 压缩** 选项与风险说明（小程序端需额外 DRACOLoader，主仓库当前未强制接入）。
4. **授权**：素材必须 **可嵌入商用 App 并再分发到小程序包体或 CDN**；在交付物中写明 **许可证名称 + 链接或截图**。
5. **骨骼**：必须 **带骨骼（SkinnedMesh）**，T-Pose 或 A-Pose；骨骼命名需 **导出文档**（中英文对照表：`实际骨骼名 → 逻辑部位：胸/腰/臀/臂/腿/根`），方便主仓库写 `traverse` 映射。
6. **坐标系**：导出时注明 **前向、向上轴**（Y-up / Z-up），与 three.js 默认 **Y-up** 一致为佳；若不一致，在文档里写 **修正旋转/缩放** 步骤。

### 你必须在本项目内自行完成（不要让产品负责人写代码）

1. **选型或制作**：在可商用前提下，选择现成低模或自行建模，完成 **UV、材质（可极简 PBR 或纯色）、骨骼、蒙皮**。
2. **导出**：从 DCC（如 Blender）导出 **glTF 2.0**，并给出 **Blender 版本与导出插件设置**。
3. **自测**：在 **浏览器** 用 Three.js **GLTFLoader** 加载 GLB，确认无报错、无破面、无异常缩放。
4. **实现「比例驱动」原型**（任选其一，推荐 A）：
   - **A**：在浏览器单页 `index.html + main.js` 中，根据输入框或 JSON（身高、各围度）计算 `bone_mapping_draft.md` 中的系数，对对应骨骼 `scale` 进行设置，每帧或变更时 `updateMatrixWorld(true)`。
   - **B**：提供 **Node 脚本** 读 JSON 输出各骨骼目标 scale（不一定要在小程序里跑，仅作逻辑验证）。
5. **写清交付物**：列出文件树、版本号、**最终拷贝到主仓库的路径建议**（见下节「主仓库对接路径」）。
6. **写 README**：包含如何运行本地预览（`npx serve` 或 `python -m http.server`）、如何替换测试数据。

### 参考数值（可写进你的原型作默认值）

- 参考身高 `H₀ = 170` cm；参考围度可用：`胸 95 / 腰 80 / 臀 95 / 臂 32 / 大腿 55 / 小腿 36`（与 `bone_mapping_draft.md` 一致即可）。
- 缩放系数需 **clamp**（例如 0.85～1.2），避免极端输入拉破模型。

### 主仓库对接路径（供你在 README 里写死）

将最终 **`body_male.glb` / `body_female.glb`**（或合并为一个）建议放到：

```
fitness-coach-app/miniprogram/assets/models/
```

并在说明中写：主仓库需在 **`body-gltf` 组件或新建组件** 中把 `modelPath` 指向上述文件，并在加载完成后遍历骨骼应用 scale（具体代码由主仓库迭代）。

### 验收标准（承接方自检）

- [ ] GLB 在 **three.js r108 左右** 能加载，无控制台红错。
- [ ] 骨骼列表文档完整，至少覆盖：根、脊柱、胸、腰、髋、上臂、前臂、大腿、小腿（左右）。
- [ ] 原型中改身高/腰围，视觉上有 **可感知变化**，无严重穿模。
- [ ] 授权与文件大小说明齐全。

## 必须留给「产品负责人 / 仓库主」本人做的事（承接方只写文档，不代操作）

以下步骤 **无法** 由模型项目替代，需主仓库维护者在本机执行：

### 1. 微信开发者工具与账号

1. 安装 **微信开发者工具**，用小程序账号登录（或测试号）。
2. **导入** 主仓库 `fitness-coach-app` 根目录（含 `project.config.json`）。

### 2. 把 GLB 放进主仓库

1. 从本（模型）项目 **复制** 最终 `*.glb` 到：  
   `fitness-coach-app/miniprogram/assets/models/`
2. Git 提交时注意 **大文件** 是否影响仓库；必要时用 **Git LFS** 或 **CDN**（CDN 需配置合法域名）。

### 3. npm 与 threejs（主仓库已有）

1. 在终端执行：  
   `cd fitness-coach-app/miniprogram && npm install`  
2. 微信开发者工具：**工具 → 构建 npm**（若使用 `require('threejs-miniprogram')` 的写法；主仓库若已用 `miniprogram_npm` 拷贝脚本，以主仓库 README 为准）。

### 4. 合法域名（真机 / 正式版）

1. 若 GLB 从 **HTTPS 服务器** 下载：在微信公众平台配置 **downloadFile 合法域名**。
2. 开发阶段可在开发者工具 **详情 → 本地设置** 勾选 **不校验合法域名**（仅开发用）。

### 5. 后端地址

1. 打开 `fitness-coach-app/miniprogram/app.js`，将 `globalData.apiBase` 设为 **正在运行的后端**（如 `http://127.0.0.1:3000`），端口与终端一致。

### 6. 商务与法务

1. 确认 GLB 的 **商用授权** 与 **隐私/肖像** 无纠纷（承接方提供许可证副本，负责人最终确认）。
